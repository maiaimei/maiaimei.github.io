一、思路骨架

maiaimei

# 一、思路骨架

  1. 选模式：NAT 最省事，虚拟机借宿主机 IP 上网；桥接会让虚拟机直接占用局域网 IP，容易和别人的地址冲突。
  2. 定网段：在 VMware 的虚拟网络编辑器里确认 VMnet8 的子网和网关，记下来。
  3. 避冲突：静态 IP 要避开 DHCP 地址池，或干脆把这段地址从池子里划出去。
  4. 认网卡与管理器：在 Ubuntu 里查网卡名（常见 ens33），确认是 netplan 还是 NetworkManager 在管网络。
  5. 写配置：关掉 DHCP，写死 IP/掩码、网关、DNS。YAML 只用空格缩进。
  6. 先试后落：netplan try 有一段时间自动回滚的保险，通过后再 apply。
  7. 分层验证：IP → 网关 → 外网 IP → 域名，逐层 ping，坏了能立刻定位是哪一层。

# 二、操作手册

# 第 1 步：VMware 侧

  1. 以管理员身份运行 VMware Workstation，菜单 编辑 → 虚拟网络编辑器。
  2. 选中 VMnet8，确认已勾选“NAT 模式”和“将主机虚拟适配器连接到此网络”。
  3. 记下子网 IP 和子网掩码。
  4. 点 NAT 设置，记下网关 IP（通常是 xxx.xxx.xxx.2）。
  5. 点 DHCP 设置，记下地址池范围，静态 IP 要落在池子外面。
  6. 虚拟机设置 → 网络适配器，选 NAT 模式。
配置项 示例值
虚拟网络 VMnet8（NAT 模式）
子网掩码 255.255.255.0
子网 IP / 网络地址（不可用） 192.168.134.0
网关 IP 192.168.134.2
DHCP 池 192.168.134.128 ~ 192.168.134.254
广播地址（不可用） 192.168.134.255
可用静态 IP 范围 192.168.134.3 ~ 192.168.134.127
DNS 114.114.114.114、8.8.8.8

网关是 192.168.134.2，所以 .1 虽然技术上可用，但一般留给路由器/网关预留，建议从 .3 开始用。

# 第 4 步：写配置

编辑 /etc/netplan/ 下已有的那个 yaml（没有就新建 99-static.yaml），改成：

network:
  version: 2
  renderer: networkd    # 桌面版保持 NetworkManager
  ethernets:
    ens33:             # 换成你实际的网卡名
      dhcp4: false
      addresses:
        - 192.168.136.128/24
      routes:
        - to: default
          via: 192.168.136.2
      nameservers:
        addresses: [114.114.114.114, 8.8.8.8]

ip route show default              # 网关是否正确
resolvectl status | grep -A2 "DNS Servers"   # DNS 是否写入
ping -c 3 192.168.136.2            # 通：虚拟机到网关 OK
ping -c 3 114.114.114.114          # 通：能出外网
ping -c 3 baidu.com                # 通：DNS 解析 OK

# 三、出问题这样查

症状 大概率原因
netplan apply 报 YAML 错误 缩进用了 Tab 或冒号后缺空格
IP 没变 网卡名写错，或另一个 yaml 文件覆盖了你这份
能 ping 通网关但上不了外网 网关 IP 填错（填成 .1 而不是 .2）
能 ping 通外网 IP 但打不开网址 DNS 没写上或写错
重启后 IP 又变了 cloud-init 在重写配置
宿主机 ping 不通虚拟机 Windows 防火墙拦截，或 VMware 服务没启动

针对后两条：

# 禁止 cloud-init 管网络，然后重启
echo "network: {config: disabled}" | sudo tee /etc/cloud/cloud.cfg.d/99-disable-network-config.cfg
sudo reboot

宿主机侧检查 VMware NAT Service、VMware DHCP Service 是否在运行，虚拟网卡 VMnet8 有没有被禁用。

改坏了就还原备份：sudo rm /etc/netplan/*.yaml && sudo cp /root/netplan-backup-*/\* /etc/netplan/ && sudo netplan apply。

# 四、两条捷径

  • 桌面版改用图形界面：设置 → 网络 → 有线 → IPv4 → 手动，填地址/网关/DNS，最不容易出错。
  • 改成在 VMware 侧固定：DHCP 设置里把地址池起止都设成同一个 IP，再按 MAC 绑定，虚拟机内部什么都不用改，适合多台机器统一管。

# 补充提醒

  • 你举例的“22.4”如果真是其他版本号，命令一样适用，只是默认 yaml 文件名可能不同，以 ls /etc/netplan/ 的实际结果为准。
  • 如果走桥接而不是 NAT，网关和 DNS 要填你家里路由器的地址（如 192.168.1.1），不能用 VMware 的 .2，而且静态 IP 要和宿主机同网段、同样避开路由器的 DHCP 池。
  • 如果之后要搭多台虚拟机做集群，建议把静态 IP 连续分配（如 .128、.129、.130），并在宿主机的 C:\Windows\System32\drivers\etc\hosts 里写上 IP 与主机名的映射，SSH 时就不用记 IP 了。
