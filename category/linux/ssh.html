SSH 知识点笔记

maiaimei 2026/11/15 ssh

# 一、SSH 是什么

# 1. 基本概念

  • SSH（Secure Shell）：一种加密的网络传输协议，用于在不安全的网络中安全地进行远程登录、文件传输和命令执行。
  • 默认端口：22
  • 主要作用：替代明文传输的 Telnet、FTP 等协议，防止密码和数据被窃听或篡改。

# 2. 核心功能

功能 说明
远程登录 加密的命令行访问（如 ssh user@host）
文件传输 基于 SSH 的 scp、sftp
端口转发 本地/远程/动态端口转发，实现安全隧道
命令执行 远程执行单条命令并获取结果

# 3. 加密机制

  • 采用 非对称加密（RSA、ECDSA、Ed25519 等）进行身份验证和密钥交换
  • 会话数据使用 对称加密（AES 等）保护
  • 使用 消息认证码（MAC） 防止数据篡改

# 二、SSH 免密登录

# 1. 核心思路

本质：用密钥对替代密码验证

图中步骤 实际 SSH 行为 技术分析
1. 生成密钥对 （客户端本地） ssh-keygen 客户端本地生成私钥（严格保密）和公钥，图中客户端上下均标注密钥对，符合本地持有全量密钥的设定。
2. 公钥上传 （保存到服务端） ssh-copy-id 仅公钥被传输并追加到服务端的 ~/.ssh/authorized_keys，私钥始终不离客户端，符合“公钥可公开”原则。
3. 连接请求 SSH 握手 客户端发起登录请求，声明用户及可用的公钥指纹。
发送随机挑战 （服务端 → 客户端） Challenge（随机数/会话 ID） 服务端生成随机挑战，明文发送（无需加密），用于防止重放攻击。
用私钥签名，返回 （客户端 → 服务端） 数字签名（Sign） 客户端用本地私钥对挑战进行签名（如 RSA/Ed25519 签名），这是核心修正点，是签名而非解密。
验证通过 （服务端本地） 公钥验签（Verify） 服务端用 authorized_keys 中的公钥验证签名合法性，验证通过即允许登录，全程密码未参与。

# 2. 操作手册

# 步骤 1：生成本地密钥对

# 推荐使用 Ed25519 算法（更安全、性能更好）
ssh-keygen -t ed25519 -C "your_email@example.com"

# 如果系统不支持 Ed25519，使用 RSA（至少 4096 位）
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"

执行过程中的提示：

  • Enter file in which to save the key：直接回车使用默认路径（~/.ssh/id_ed25519）
  • Enter passphrase：建议设置密码短语（为空则私钥无额外保护，安全性降低）
  • Enter same passphrase again：重复确认

生成后的文件：

~/.ssh/
├── id_ed25519      # 私钥（严格保密，权限 600）
└── id_ed25519.pub  # 公钥（可以公开，权限 644）

# 三、常见问题排查

问题 排查方法
仍然要求输入密码 检查服务器 ~/.ssh 目录权限（700）、authorized_keys 权限（600）
连接超时 检查服务器防火墙是否放行 22 端口
密钥被拒绝 确认 sshd_config 中 PubkeyAuthentication yes
多个密钥冲突 使用 ssh -v user@host 查看详细调试信息

调试命令：

# 详细输出连接过程
ssh -v user@remote_host

# 指定私钥文件
ssh -i ~/.ssh/id_ed25519 user@remote_host

# 四、常用命令速查

# 基本连接
ssh user@host

# 指定端口
ssh -p 2222 user@host

# 远程执行命令
ssh user@host "ls -la /tmp"

# 文件传输
scp file.txt user@host:/path/to/dest/
scp -r folder/ user@host:/path/to/dest/

# 端口转发（本地）
ssh -L 8080:localhost:80 user@host

# 生成密钥
ssh-keygen -t ed25519

# 上传公钥
ssh-copy-id user@host
