VMware Workstation Pro 虚拟机搭建

maiaimei 2026/11/14 VMware

本手册旨在提供一套跨平台的虚拟机搭建方法论与可复用流程。

适用对象：VMware Workstation Pro 17.x / 26H1（Windows 或 Linux 宿主机）

适用 Guest：Windows / Linux 发行版 / BSD / 其他 x86 系统

定位：方法论 + 可复用操作流程，不绑定任何单一操作系统

VMware Workstation Pro 是 VMware（现属博通 Broadcom）出品的桌面虚拟机软件，简单说就是：

在你现在的 Windows 或 Linux 电脑里，再“开”出几台独立的电脑。

它属于 Type-2 桌面 Hypervisor（虚拟机监视器）：安装在宿主机(Host)系统上，再在里边创建“虚拟机（Guest）”，每台虚拟机可以装不同的操作系统。

# 一、通用思路骨架

# 1. 逻辑层级

宿主机 Host（物理机，Windows/Linux/macOS）
 └── 虚拟化软件 VMware Workstation Pro（Type-2 虚拟化层）
      ├── 虚拟网络（VMnet0 桥接 / VMnet8 NAT / VMnet1 仅主机）
      └── 虚拟机 Guest（虚拟硬件 + 任意 Guest OS）
           ├── CPU / 内存 / 磁盘 / 网卡（虚拟化硬件）
           └── 操作系统（Windows / Linux / BSD / 其他）

# 3. 虚拟网络模式

VMware 提供了多种虚拟网络模式，本质是在宿主机里“虚拟出不同的交换机和网络环境”。选择哪种模式，取决于你的虚拟机是否需要上网、是否需要被局域网其他设备访问、是否需要隔离。

本文按“从通用到特殊”的顺序，梳理四种核心网络模式的特征与用途。

# 3. 1. 核心模式速查表

模式 VMware 虚拟交换机 网络特征 典型用途
桥接模式（Bridged） VMnet0 Guest 与 Host 同网段，等同局域网一台独立机器 需要被局域网其他设备访问
网络地址转换模式（NAT） VMnet8 Guest 通过 Host 上网，内部独立私有网段 个人学习、开发、固定静态 IP
仅主机模式（Host-Only） VMnet1 仅 Host ↔ Guest 互通，无外网 隔离实验、内网模拟
自定义/LAN 区段 用户自建 完全隔离或自定义拓扑 多机组网实验

# 3. 2. 桥接模式（Bridged / VMnet0）

通俗理解：把虚拟机直接“插”到物理局域网的交换机上，它和你的宿主机是平级的“邻居”。

核心特征：

  • 虚拟机的网络配置与物理机处于同一网段。
  • 虚拟机可以直接访问物理机的网络资源，反之亦然（类似连到同一个交换机）。
  • 虚拟机 IP 需与物理机同网段，若需联网，网关与 DNS 必须与物理机网卡保持一致。

优缺点：

  • ✅ 优点：提供最大的灵活性和网络访问权限，外部设备（如手机、其他电脑）可直接访问虚拟机。
  • ❌ 缺点：消耗局域网真实 IP 资源；若网络环境对 IP 管理严格（如公司网络），可能受限或易引发 IP 冲突。

适用场景：搭建需被局域网其他设备直接访问的服务（如局域网文件服务器、外部设备调试）。

# 3. 3. 网络地址转换模式（NAT / VMnet8）

通俗理解：VMware 造了一个“私有小局域网”，虚拟机住里面，上网时“借宿主机的网络”出去（类似家里路由器给手机 NAT 上网）。

核心特征：

  • 虚拟机通过物理机的网卡访问外部网络，同时保护虚拟机 IP 不被外部直接访问。
  • 内部使用独立私有网段（如 192.168.134.0/24），VMware 充当网关（通常 .2）做地址转换。
  • （详细 IP/网关/DHCP 速查可参考前文《VMware NAT 网络配置与 IP 速查指南》）

优缺点：

  • ✅ 优点：节省 IP 资源，不占用局域网真实 IP，适合 IP 管理严格的网络环境；个人开发最省心。
  • ❌ 缺点：外部网络默认无法直接访问虚拟机（需额外配置端口转发）。

适用场景：个人学习、日常开发、需要固定静态 IP 且只需虚拟机主动连外网的场景（最常用）。

# 3. 4. 仅主机模式（Host-Only / VMnet1）

通俗理解：一个“与世隔绝”的封闭内网，只有宿主机和虚拟机之间能“说话”，断绝外网。

核心特征：

  • 创建了封闭的虚拟网络，仅包含主机和虚拟机之间的通信。
  • 虚拟机只能与宿主机通信，无法访问外部网络（无默认网关出网）。
  • 对应虚拟交换机 VMnet1。

优缺点：

  • ✅ 优点：极致隔离，安全，适合纯内网调试。
  • ❌ 缺点：默认无外网，若需上网需复杂共享配置。

适用场景：隔离实验、内网模拟、内部测试或开发环境（如模拟黑客靶场、内网渗透测试）。

# 3. 5. 自定义 / LAN 区段（用户自建）

通俗理解：自己画一张“网络拓扑图”，想怎么连就怎么连，完全由你定义。

核心特征：

  • 不绑定默认的 VMnet0/1/8，由用户自建虚拟网络。
  • 可实现完全隔离或复杂的自定义拓扑（如多台虚拟机组成独立网络，不与宿主机通联）。

适用场景：多机组网实验（如模拟企业多网段架构、集群部署、复杂路由实验）。

# 3. 6. 一句话总结（如何选模式）

  • 要被局域网别人访问 → 选桥接 (Bridged / VMnet0)
  • 自己学习开发、只要虚拟机能上网 → 选 NAT (VMnet8)（推荐默认）
  • 纯内网隔离、绝密实验 → 选仅主机 (Host-Only / VMnet1)
  • 复杂多机拓扑、完全自定义 → 选自定义 / LAN 区段

学习/开发推荐：NAT 模式，网络可控、不占局域网 IP、静态 IP 好管理。

# 4. 虚拟硬件配置

资源 建议（起步） 说明
CPU 2 vCPU 多数 OS 够用；编译/服务可适当加
内存 2–4 GB Windows ≥ 4GB；轻量 Linux 1–2GB
磁盘 40–60 GB（动态分配） 拆分成多个文件，方便迁移
网卡 1 块（NAT） 后续可加第二块做多网段实验
固件 UEFI（新 OS）/ BIOS（旧 OS） 影响安装引导方式

# 阶段 3：新建虚拟机流程

  1. 文件 → 新建虚拟机
  2. 配置类型：
    • 典型（推荐）：快速上手
    • 自定义（高级）：需调固件/磁盘控制器/兼容性时选
  3. 安装来源：
    • 选「安装程序光盘映像文件 (iso)」→ 浏览到你的 ISO
    • 或「稍后安装操作系统」（先建壳再挂 ISO）
  4. 客户机操作系统：
    • 选对应类型（Windows / Linux / Other）和版本
    • Linux 下具体发行版选对（影响 VMware 自动优化）
  5. 虚拟机名称 + 位置：
    • 名称：win10-dev / rocky9-srv / freebsd14 等
    • 位置：放在非系统盘、空间充足的目录
  6. 磁盘：
    • 最大大小：按 OS 需求（Windows 60GB+，Linux 20–40GB）
    • 选「将虚拟磁盘拆分成多个文件」
    • 勾选「立即分配所有磁盘空间」→ 不勾选（用动态分配）
  7. 自定义硬件（关键）：
    • 内存：按阶段 0 建议
    • 处理器：2 vCPU
    • 网络适配器：NAT（默认）
    • CD/DVD：指向 ISO 文件
    • 显示器：勾选「加速 3D 图形」（桌面 OS 需要）
    • 移除无用设备：打印机、声卡（服务器可去）
  8. 点「完成」

步骤 通用操作

# 阶段 5：虚拟网络配置

网络配置是虚拟机落地的核心。虽各 OS 界面有差异，但网络逻辑通用。本阶段采用通用 NAT 静态 IP 方案（VMnet8），先配虚拟化层，再配客户机。

# 5.1 虚拟化层配置

VMware 侧一次设置，所有 Guest 共用，后续仅需在各系统内部固定 IP 即可。

以 Windows 为例配置：

  1. 以管理员身份运行 VMware Workstation，菜单 编辑 → 虚拟网络编辑器。
  2. 选中 VMnet8，确认已勾选“NAT 模式”和“将主机虚拟适配器连接到此网络”。
  3. 记下子网 IP 和子网掩码。
  4. 点 NAT 设置，记下网关 IP（通常是 xxx.xxx.xxx.2）。
  5. 点 DHCP 设置，记下地址池范围，静态 IP 要落在池子外面。
  6. 虚拟机设置 → 网络适配器，选 NAT 模式。
参数 推荐值 说明
网络类型 NAT VMnet8
子网 IP 192.168.X.0 X 任选（如 134），即网络地址
子网掩码 255.255.255.0 /24
网关 IP 192.168.X.2 VMware NAT 设备地址
DHCP 池 192.168.X.128 ~ .254 自动分配区间
可用静态范围 .3 ~ .127 手动分配安全区，网关是 192.168.134.2，所以 .1 虽然技术上可用，但一般留给路由器/网关预留，建议从 .3 开始用。

# 5.2 客户机侧配置

VMware 层打通后，需在客户机内固定 IP。核心原则：IP 落在 DHCP 池（.128~.254）之外，网关统一填 .2。

实操前必看（通用步骤）：

  1. 确认网卡名：Linux 先敲 ip addr（常见 eth0/ens33/ens18），Windows 看“以太网”状态。
  2. IP 取值：前文 DHCP 池是 .128~.254，静态 IP 请选 .3~.127（如示例 192.168.134.10）。
  3. 网关/DNS：网关必填 192.168.134.2（VMware 虚拟路由器），DNS 用 114.114.114.114 或 8.8.8.8。
  4. 生效验证：配完必测 ping 192.168.134.2（通网关）、ping www.baidu.com（通外网）。

以下按 OS 分类实操（示例 IP 取 192.168.134.10）。

Linux（使用 netplan 的发行版：Ubuntu 18.04+ / Debian 12+）

# /etc/netplan/01-static.yaml
# 注意：eth0 需替换为实际网卡名（ip addr 查看），IP 需在 .3~.127 之间
network:
  version: 2
  renderer: networkd
  ethernets:
    eth0:
      dhcp4: false
      addresses: [192.168.134.10/24]  # 静态IP/掩码
      routes:
        - to: default
          via: 192.168.134.2          # 网关（NAT设备）
      nameservers:
        addresses: [114.114.114.114, 8.8.8.8]
# 保存后执行：sudo netplan apply

# 三、常见故障排查

现象 排查方向
虚拟机无法启动 宿主机虚拟化是否开启；VMware 版本兼容性
无 IP / 网络不通 网络模式选对没；网关是否 .2；防火墙
宿主机 ping 不通 Guest Host 防火墙；VMnet8 适配器是否被禁
增强工具装不上 Guest 内核版本太新/太旧；缺编译工具链
磁盘空间不足 动态磁盘实际占用变大；快照太多
时间不同步 VMware 设置里勾选「同步客户机时间与主机」
性能卡顿 内存不足；没开 3D 加速；杀毒扫描虚拟机目录
