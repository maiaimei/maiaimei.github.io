PostgreSQL `pg_hba.conf` 完全解读

PostgreSQL pg_hba.conf 完全解读

maiaimei 2026/11/15 PostgreSQL

前置说明：pg_hba.conf 是 PostgreSQL 的客户端认证配置文件，全称 PostgreSQL Host-Based Authentication Configuration。

它决定了：谁能连、从哪里连、连哪个库、用什么方式认证。

官方网址：https://www.postgresql.org/docs/current/auth-pg-hba-conf.html

# 如何查看 pg_hba.conf

连接到 PostgreSQL 后执行：

SHOW hba_file;
1

返回结果类似：

/var/lib/postgresql/data/pg_hba.conf
/etc/postgresql/17/main/pg_hba.conf
1
2

该路径即为当前实例实际加载的配置文件位置。

# pg_hba.conf 基础语法

pg_hba.conf 文件中每一行代表一条连接规则，格式如下：

TYPE  DATABASE  USER  ADDRESS  METHOD  [OPTIONS]
1
字段 含义 常见值
TYPE 连接类型 local：通过 Unix Socket 连接（不走网络）
host：通过 TCP/IP 连接（走 IP）
DATABASE 允许连接的数据库 all, postgres, 具体库名
USER 允许连接的用户 all, postgres, 具体用户名
ADDRESS 来源 IP 或网段 127.0.0.1/32, 0.0.0.0/0, ::1/128
METHOD 认证方式 trust
peer：仅限 local（Unix Socket），读取当前 Linux 用户名，要求它 = 数据库用户名，不验密码
ident：仅限 host（TCP/IP），且依赖客户端 ident server
md5
scram-sha-256：用数据库用户密码认证（最常用）
OPTIONS 用于指定身份验证方法的选项，格式：name=value map=xxx：引用 pg_ident.conf 里的映射，允许 Linux 用户 ≠ 数据库用户

⚠️ 注意：规则匹配遵循自上而下、首次命中即生效，后面的不再看原则。

# 逐条规则解读 + 命中示例

PostgreSQL 的客户端认证由 pg_hba.conf（主机基础架构认证）和 pg_ident.conf（用户身份映射）共同控制。

核心原则是：pg_hba.conf 从上往下匹配，第一条命中即生效；peer 认证直接读取操作系统用户，配合 map 可实现 Linux 用户到数据库用户的映射。

# 一、身份映射配置（pg_ident.conf）

pg_ident.conf文件与pg_hba.conf文件在同一目录。

# MAPNAME       SYSTEM-USERNAME         PG-USERNAME
ci_map       biz_auto_admin         biz_owner_admin
1
2

含义：定义名为 ci_map 的映射规则。当操作系统用户为 biz_auto_admin 时，在 PostgreSQL 中可被视为数据库用户 biz_owner_admin。

前提：此映射仅在 pg_hba.conf 中对应规则声明了 peer map=ci_map 时才会被触发。

官方地址：https://www.postgresql.org/docs/current/auth-username-maps.html

# 二、认证规则逐条解读与命中示例（pg_hba.conf）

# 规则 1：postgres 超级用户本地 socket 免密

# Database administrative login by Unix domain socket
local   all     postgres    peer
1
2

含义：Linux 用户 postgres 通过 socket 连任意数据库，免密。

✅ 命中示例：

sudo -u postgres psql
sudo -u postgres psql -d mydb
1
2

❌ 不命中：

psql -U postgres          # 当前是普通用户，peer 要求 Linux 用户 = postgres
1

# 规则 2：biz_auto_admin 映射为 biz_owner_admin 连 bizdb

local   bizdb   biz_owner_admin   peer map=ci_map
1

pg_ident.conf 对应：

ci_map   biz_auto_admin   biz_owner_admin
1

含义：Linux 用户 biz_auto_admin 通过 socket 连 bizdb 数据库，声明自己是 biz_owner_admin，查映射表放行。

✅ 命中示例：

sudo -u biz_auto_admin psql -U biz_owner_admin -d bizdb
1

匹配过程：

  1. TYPE=local ✓（走 socket）
  2. DATABASE=bizdb ✓
  3. USER=biz_owner_admin ✓
  4. 命中！使用 peer map=ci_map
  5. 查 pg_ident.conf：biz_auto_admin → biz_owner_admin ✓ 放行

❌ 不命中的情况：

命令 原因
sudo -u biz_auto_admin psql 没写 -U，默认用 biz_auto_admin 当数据库用户，不匹配 biz_owner_admin
sudo -u other_user psql -U biz_owner_admin -d bizdb Linux 用户不在映射表里
psql -h 127.0.0.1 -U biz_owner_admin -d bizdb 走 TCP 不是 socket，不匹配 local

# 规则 3：兜底——所有本地 socket 连接走 peer

local   all     all     peer
1

含义：任何 Linux 用户通过 socket 连任何数据库，要求 Linux 用户名 = 数据库用户名。

✅ 命中示例：

# 假设 Linux 有用户 alice，数据库也有角色 alice
sudo -u alice psql
sudo -u alice psql -d mydb -U alice
1
2
3

❌ 不命中：

psql -U someuser    # Linux 用户 ≠ someuser，peer 失败
1

# 规则 4：IPv4 本地 TCP 连接（密码认证）

host    all     all     127.0.0.1/32    scram-sha-256
1

含义：从 127.0.0.1 来的 TCP 连接，用密码登录。

✅ 命中示例：

psql -h 127.0.0.1 -U postgres -d mydb
psql -h 127.0.0.1 -U biz_owner_admin -d bizdb
1
2

匹配过程：

  1. TYPE=host ✓（走 TCP）
  2. ADDRESS=127.0.0.1 ✓
  3. DATABASE / USER = all ✓
  4. 使用 scram-sha-256 密码认证

❌ 不命中：

psql -h localhost ...   # 可能走 IPv6（::1），命中下一条
1

# 规则 5：IPv6 本地 TCP 连接（密码认证）

host    all     all     ::1/128    scram-sha-256
1

含义：从 ::1（IPv6 的 localhost）来的连接，密码认证。

✅ 命中示例：

psql -h ::1 -U postgres -d mydb
# 或系统解析 localhost → ::1 时
psql -h localhost -U postgres -d mydb
1
2
3

# 规则 6：本地 replication socket 连接

local   replication     all     peer
1

含义：用于流复制，通过 socket 连接，peer 认证。

✅ 命中示例：

sudo -u postgres pg_basebackup ...
sudo -u postgres psql -c "START_REPLICATION ..."
1
2

# 规则 7：IPv4 replication 连接

host    replication     all     127.0.0.1/32    scram-sha-256
1

✅ 命中示例：

pg_basebackup -h 127.0.0.1 -U replicator -D /var/lib/postgresql/data
1

# 规则 8：IPv6 replication 连接

host    replication     all     ::1/128    scram-sha-256
1

✅ 命中示例：

pg_basebackup -h ::1 -U replicator -D /var/lib/postgresql/data
1

# 修改配置后如何生效

编辑 pg_hba.conf 文件后，需重新加载配置：

SELECT pg_reload_conf();
1

随后重新建立连接进行测试，以验证规则是否按预期生效。

# 查看当前已生效规则

PostgreSQL 提供了 pg_hba_file_rules 视图，可直接读取内存中正在使用的 HBA 规则（注意：它反映的是已加载的状态，而非磁盘文件未重载前的状态）。

# 一、查看完整规则列表

SELECT line_number,
       type,
       database,
       user_name,
       address,
       auth_method
FROM pg_hba_file_rules
ORDER BY line_number;
1
2
3
4
5
6
7
8

💡 说明：

  • line_number：对应 pg_hba.conf 文件中的行号，方便对照。
  • type：local（Unix Socket）或 host（TCP/IP）。
  • auth_method：认证方式（如 peer、scram-sha-256、md5、带 map= 的 peer 等）。
  • 此查询能直观展示规则顺序，快速发现“为何没走映射”、“为何未提示输入密码”等问题。

# 二、筛选特定用户/角色的规则

如需确认某个用户或某类用户（如超级用户、业务用户、通配符 all）的认证方式，可执行：

SELECT *
FROM pg_hba_file_rules
WHERE user_name IN ('postgres', 'biz_app_rw', 'all')
ORDER BY line_number;
1
2
3
4

💡 场景：

  • 排查“为什么 postgres 用户突然不需要密码了”（通常命中了 local all postgres peer）。
  • 确认业务用户 biz_app_rw 是走密码认证（scram-sha-256）还是身份映射（peer map=xxx）。

# 排错口诀与实战建议

“看 TYPE、看 USER、看 METHOD、看顺序”

  1. TYPE：有无 -h 参数？无则走 local（socket），有则走 host（TCP）。
  2. USER：-U 指定的数据库用户是谁？peer 认证要求 Linux 用户 = DB 用户（或通过 map 映射）。
  3. METHOD：peer 不验密码，直接读系统用户；scram-sha-256/md5 才提示输密码。
  4. 顺序：pg_hba.conf 从上往下，第一条命中即停。用 pg_hba_file_rules 查看顺序最稳妥。

注意：

  • peer 认证 + ident 映射，只能在 local（Unix Socket）下使用
  • TCP/IP 连接不支持 peer / ident
  • 只要命令里带了 -h，就一定走 TCP/IP，不可能用 peer 免密。

这是 PostgreSQL 的设计限制，不是配置问题。

# 核心要点速查

场景 操作
快速确认规则 SELECT * FROM pg_hba_file_rules;
查看文件路径 SHOW hba_file;
修改配置 编辑 pg_hba.conf
重载配置 SELECT pg_reload_conf();

# 常见错误速查

报错 原因 解决
Peer authentication failed 走 socket + peer，但 Linux 用户 ≠ 数据库用户 加 -h 127.0.0.1 或加 map=
role "xxx" does not exist 数据库里没这个角色，且 peer 不验密码直接拒 建 role 或指定正确的 -U
改了配置不生效 没 reload SELECT pg_reload_conf();

# 总结

  • 改配置 → 重载 → 查视图：形成闭环，避免“文件改了但数据库没加载”的误判。
  • pg_hba_file_rules 是排错利器：直接反映内存规则，快速定位认证方式、映射失效、顺序错误。
  • 初学者牢记：local + peer 看 Linux 用户，host + 密码 看网络与密码；映射必须显式指定 -U 映射后的DB用户。
